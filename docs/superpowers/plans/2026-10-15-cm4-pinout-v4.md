# CM4 pinout v4 — vertical CN1/CN2 drawing, schematic-checked allocation — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Ship rev 3 of the CM4 pinout page: the CM4 drawn vertically with CN1/CN2 as schematic-style pin columns with direction arrows, a new allocation that connects CRSF_Mod, Retr_PWR, the VRX boards and the ADV7280A-M path according to the real Retr_Cross schematic, and a per-pin check (verdict + concerns) against the EasyEDA snapshot.

**Architecture:** Same single-file page (`cm4_pinout.html`) with data embedded by `tools/build.py`. Content changes live in `data/project.json` (rev 3 allocation, new `dir` and `issues` fields), `data/rationale.json`, `data/routing.json`; a new generated `data/schematic.json` (from `Review/_data/chains.json`) carries what the carrier wires to each CM4 pin, and `LIB.checkOf` derives the verdict at render time. The drawing is rebuilt around new `LIB` geometry (`padXY`, `rot`, `mm`, `sideOf`, `ARROW`).

**Tech Stack:** HTML/CSS/JS single file (no build step except `tools/build.py`); Python 3.13 `unittest`; `node --test` (node 24); Playwright (chromium) for browser tests.

**Spec:** `docs/superpowers/specs/2026-10-15-cm4-pinout-v4-design.md` — every task below cites its section (§). The spec's decision table D1–D10 and the pin tables §4.3 are the content source; `Review/*.md` and `Review/_data/chains.json` are the evidence.
